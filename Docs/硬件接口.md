# 本机适配器接口 v1

v0.2 的日常设置不再提供设备控制台。开发中通过 `model.toggleBridge()` 显式开启，或用 App 的 `--bridge-smoke` 参数临时开启 20 秒做接口检查。地址 `127.0.0.1:18457`，TCP，UTF-8 JSON Lines，每条以 `\n` 结束。仅一条活动连接，不对局域网开放。它不是通用的气泵协议；默认关闭，每次重启需重新开启。

## 适配器 → 气间

每 250–500ms 发送接触状态：

```json
{"type":"contact","version":1,"sequence":1,"pressed":true}
```

`pressed` 必须是 JSON 布尔值；`sequence` 为非负递增整数，在新连接中从 0 或 1 开始。同一连接的重复／倒序序号会被丢弃。心跳超过 3 秒未更新或连接中断，接触状态失效，计时停止。尚无压力／接触传感器算法，须由适配器根据实际硬件标定提供 `pressed`。

每行最多 2048 字节，支持拆包粘包；非法 JSON 忽略，超长输入断开。本机任意进程都可能连接此开发接口，不适合不可信共享电脑上的生产部署。

## 气间 → 适配器

约 10Hz，下游忙时丢弃中间帧，不堆积历史动作：

```json
{"type":"target","version":1,"sequence":42,"mode":"working","air":[1,0.6,1],"rgb":[[0,0,0],[0,0,0],[0,0,0]],"ttl_ms":750,"simulated":true,"contact":true}
```

- `air` 顺序固定为左、中央、右，范围 0–1。它描述期望造型，不是压力、泵占空比、阀开闭或传感器读数。
- `rgb` 顺序相同，三个 `[R,G,B]`，每通道 0–255，已经包含亮度偏好与音乐能量映射。
- `mode` 为 `working`、`resting` 或 `paused`。
- `contact` 在信号新鲜时为 true／false，信号未知时省略。
- `ttl_ms` 是未来适配器对过期输出的约定，**软件不代表已经验证的实体停机机制**。
- `simulated` 始终为 true。当前适配器只能预览／记录这些目标，不应把它们直接当作驱动命令。

退出、睡眠和失联时不要依赖最后一帧；实体适配器必须在连接断开／目标超时后自主停泵，并依据已核实的硬件气路执行相应状态。

## 开发时模拟接触

`tools/simulate_contact.py` 可以向本机接口发送模拟接触。测试自动休息需要在开发配置中将 `Preferences.contactMode` 设为 `.sensor`、工作时长设为 1 分钟，并显式开启桥接器。日常小偏好面板不显示这些开发选项。

接口冒烟可使用 `--bridge-smoke` 配合 `python3 tools/verify_bridge.py`；前者仅保持接口 20 秒。

脚本只发送本机模拟数据，不连接蓝牙、不操作实体设备。

## 实体接入还需要什么

确认三路气囊对应的泵／阀拓扑、引脚、控制与供电，确认各气囊的压力或体积反馈、目标标定、压力边界和独立保护。然后实现硬件适配器，在状态机与实体控制之间做压力闭环、充放气限速和失联处理。当前代码没有启用真实硬件的开关，也不会假定单路原型能实现三路独立充气。
